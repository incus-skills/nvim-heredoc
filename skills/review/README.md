# Review skills

This directory collects review capabilities emerging from work in this project, for possible reuse within later review cycles and across projects.

It is a working collection, not a prescribed review framework. Candidates retain the context in which they arose, the evidence for their usefulness, their limitations, and questions about transfer. Applying a candidate elsewhere is an opportunity to test and refine it, not simply to reproduce its original form.

## How to use this collection

- Read the candidate in its project context before applying it.
- Treat its distinctions and questions as aids to observation, not mandatory steps or acceptance criteria.
- Record what transfers, what needs adaptation, and what does not fit the new context.
- Preserve counterexamples and unresolved questions.
- Update a candidate when further application changes its scope or understanding.
- Promote, combine, split, defer, or retire candidates only when accumulated experience supports doing so.

The collection may develop a different structure as its contents and uses become clearer. The present layout is intentionally lightweight.

## Candidate notes

A candidate may record:

- **Origin:** the project situation or review observation that made the capability visible.
- **Purpose:** what the capability helps an observer do.
- **Useful distinctions:** concepts that should remain distinguishable when applying it.
- **Application:** where and how it has been used.
- **Evidence:** observations supporting its usefulness.
- **Limits and risks:** where it may mislead, overreach, or constrain reasoning.
- **Open questions:** what further applications could clarify.

This is a suggested set of prompts, not a required template. A candidate need not fill every field before it can be useful.
