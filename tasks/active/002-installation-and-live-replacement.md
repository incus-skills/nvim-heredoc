## Objective

Replace the previous function-wrapped heredoc ftplugin implementation with the repository's shared Lua scanner and buffer integration, using the same provisioning approach that generated the existing Bash, POSIX sh, and Zsh ftplugins.

## Work completed

- Added scripts/install.sh. It installs the canonical repository Lua modules into the Neovim configuration and emits three small function-wrapped ftplugin payloads using the project's heredoc content convention.
- The provisioner writes the three ftplugin entrypoints to after/ftplugin/{bash,sh,zsh}.lua. Each calls require("nvim-heredoc").setup_buffer().
- Added setup_buffer() to the Lua module so a provisioned ftplugin attaches only its current buffer. Attachment is exposed through vim.b.nvim_heredoc_attached for live verification.
- The provisioner supports NVIM_CONFIG_DIR for explicit targets and test installations. It replaces only the three provisioner-owned ftplugins and the three module files.
- Removed plugin/nvim-heredoc.lua. A plugin runtime entrypoint and Lazy.nvim specification are not required for this installation method.
- Updated the pinned LazyVim fixture and its negative control to load through the same per-filetype ftplugin shape generated by the provisioner.
- Replaced the LazyVim-specific installation and backup procedure with provisioning, replacement semantics, live verification, and removal instructions.
- Added tests/run-installer.sh to validate module copies, all three generated ftplugin shims, and repeat-execution stability in an isolated target configuration. The CI core job runs this installer test with a controlled glow stub.
- The updated five-job workflow passed in [run 43205842260](https://github.com/incus-skills/nvim-heredoc/actions/runs/43205842260), including the installer test, Neovim buffer integration, shell delivery, formatter preservation, and the pinned LazyVim fixture using provisioned ftplugin shims.
